# HTTP API Auth

Статус: реализовано. Документ описывает текущее поведение Auth.
Локальный адрес по умолчанию: `http://localhost:8081` (`AUTH_HTTP_ADDR`).

## Общие правила

- Регистрация и вход доступны без авторизации.
- Клиент отправляет JSON с `Content-Type: application/json`. Сейчас сервер не проверяет этот заголовок отдельно.
- Ответы обработчиков имеют `Content-Type: application/json`.
- Тело запроса ограничено 1 МиБ (1 048 576 байт).
- Неизвестные поля, неверные типы полей, повреждённый JSON и дополнительные JSON-значения отклоняются с `400`.
- Превышение размера тела также возвращает `400`; отдельного ответа `413` в текущем Auth нет.
- Email нормализуется: пробелы по краям удаляются, буквы приводятся к нижнему регистру. Пароль не обрезается и не нормализуется.
- Ошибки обработчиков имеют формат `{"error":"message"}`. Ответы маршрутизатора на неизвестный путь или неподдерживаемый метод пока используют стандартный формат Go, а не этот JSON-формат.

## Регистрация: POST /auth/register

Обязательные поля: `email` и `password`, оба — строки.
Email должен быть одним адресом без отображаемого имени.
Пароль должен содержать минимум 8 Unicode-кодовых точек и занимать максимум 72 байта в UTF-8.
Отдельное ограничение длины email сейчас не задано.

```bash
curl -i http://localhost:8081/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"email":"user@example.com","password":"password123"}'
```

Успешный ответ: `201 Created`.

```json
{
  "id": 3,
  "email": "user@example.com",
  "created_at": "2026-11-03T10:00:00Z"
}
```

`id` — положительное целое число; `created_at` — время создания в формате RFC 3339 с возможной дробной частью секунды и часовым смещением. Значения задаёт сервер. Пароль и его хеш не возвращаются.

| Код | Поле error | Причина |
| --- | --- | --- |
| `400` | `invalid JSON` | Ошибка декодирования, неизвестное поле или превышение лимита при чтении JSON |
| `400` | `expected one JSON object` | После первого JSON-значения обнаружены дополнительные данные или ошибка чтения |
| `400` | `invalid email` | Email отсутствует или не прошёл проверку |
| `400` | `invalid password` | Пароль отсутствует или не соответствует ограничениям |
| `409` | `email already taken` | Нормализованный email уже зарегистрирован |
| `500` | `internal error` | Внутренняя ошибка |

## Вход: POST /auth/login

Ожидаемые поля: `email` и `password`, оба — строки.
Правила длины пароля регистрации при входе повторно не применяются; пароль сравнивается с сохранённым bcrypt-хешем.
Отсутствующие поля не проверяются отдельно: они становятся пустыми строками и приводят к `401`, если учётные данные не подходят.

```bash
curl -i http://localhost:8081/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"user@example.com","password":"password123"}'
```

Успешный ответ: `200 OK`, заголовки `Cache-Control: no-store` и `Pragma: no-cache`.

```json
{
  "access_token": "<JWT>",
  "token_type": "Bearer",
  "expires_in": 900
}
```

`expires_in` — срок жизни токена в секундах, заданный `AUTH_JWT_TTL` (по умолчанию `15m`, то есть 900 секунд).
JWT подписан HS256 и содержит `sub` (ID пользователя), `iss = auth-service`, `aud = blog-service`, `iat` и `exp`.

| Код | Поле error | Причина |
| --- | --- | --- |
| `400` | `invalid JSON` | Ошибка декодирования, неизвестное поле или превышение лимита при чтении JSON |
| `400` | `expected one JSON object` | Дополнительные данные после первого JSON-значения или ошибка чтения |
| `401` | `invalid email or password` | Неизвестный email или неверный пароль; сообщение одинаковое |
| `500` | `internal error` | Внутренняя ошибка |

Токен предназначен для заголовка `Authorization: Bearer <JWT>` в [Blog API](blog.md).
Auth проверяет его через gRPC, а не отдельный HTTP-маршрут: контракт находится в [auth.proto](../proto/auth/v1/auth.proto).
Проверка JWT не обращается к базе и не проверяет, существует ли пользователь после выдачи токена.
