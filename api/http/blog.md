# HTTP API Blog

Статус: согласованный контракт для реализации. Сейчас Blog — заглушка; описанные маршруты ещё не работают.
Планируемый локальный адрес: `http://localhost:8080` (`BLOG_HTTP_ADDR`).

## Общие правила

- Запросы с телом используют JSON; клиент передаёт `Content-Type: application/json`.
- Ответы с телом имеют `Content-Type: application/json`.
- Все ошибки имеют формат `{"error":"message"}`; внутренние подробности SQL и gRPC клиенту не передаются.
- ID статьи — десятичное положительное целое число в диапазоне `int64`. Неверный формат, ноль, отрицательное значение или переполнение дают `400`.
- Даты возвращаются в UTC в формате RFC 3339 с возможной дробной частью секунды.
- Чтение публичное и не зависит от доступности Auth. Заголовок авторизации на публичных маршрутах не требуется и не проверяется.

## Статья в ответах

```json
{
  "id": 10,
  "author_id": 3,
  "title": "Первая статья",
  "body": "Текст статьи",
  "created_at": "2026-11-03T10:00:00Z",
  "updated_at": "2026-11-03T10:00:00Z"
}
```

Все поля присутствуют. `id` и `author_id` — положительные целые числа.
Идентификаторы и даты задаёт сервер. При создании даты совпадают; при изменении `created_at` сохраняется, `updated_at` устанавливается в текущее время.

## Тело создания и изменения

```json
{
  "title": "Первая статья",
  "body": "Текст статьи"
}
```

- Оба поля обязательны, имеют тип string и не могут быть `null`.
- У `title` удаляются пробельные символы по краям; результат должен содержать от 1 до 200 Unicode-кодовых точек.
- `body` содержит от 1 до 50 000 Unicode-кодовых точек и не состоит только из пробельных символов. Исходные пробелы и переносы строк сохраняются.
- Тело запроса ограничено 1 МиБ (1 048 576 байт); превышение даёт `413`.
- Неверный JSON, неизвестные поля, неверные типы, отсутствующие поля и дополнительные JSON-значения дают `400`.
- `author_id`, `id` и даты не принимаются от клиента: это неизвестные поля.
- `PUT` заменяет оба текстовых поля полностью; частичное обновление не предусмотрено.

## Авторизация

Для `POST`, `PUT` и `DELETE` обязателен заголовок:

```http
Authorization: Bearer <JWT>
```

Blog передаёт сырой JWT в gRPC `AuthService.ValidateToken` и получает положительный `user_id`.
Из него определяется автор статьи; локально Blog JWT не проверяет и секрет подписи не получает.
Соединение с Auth переиспользуется; deadline каждого вызова — 2 секунды.

- Отсутствующий или некорректный заголовок, пустой, неверный или просроченный токен → `401`.
- gRPC `Unauthenticated` → `401`.
- Недоступность, таймаут или другой сбой проверки Auth → `503`; операция со статьёй не выполняется.
- Сначала проверяется авторизация, затем параметры и тело запроса, затем существование статьи и права владельца.
- Для авторизованного пользователя отсутствующая статья → `404`, существующая чужая статья при изменении или удалении → `403`.

## Список: GET /articles

```bash
curl -i 'http://localhost:8080/articles?limit=20&offset=0'
```

| Параметр | По умолчанию | Допустимое значение |
| --- | --- | --- |
| `limit` | `20` | Целое число от 1 до 100 |
| `offset` | `0` | Целое число от 0 до максимального значения `int64` |

Пустые, нецелые, выходящие за диапазон и повторяющиеся значения этих параметров дают `400`. Неизвестные query-параметры также дают `400`.
Сортировка фиксированная: `created_at DESC, id DESC`.
При изменениях данных между запросами пагинация по offset может давать повторы или пропуски.

Успешный ответ: `200 OK`.

```json
{
  "items": [
    {
      "id": 10,
      "author_id": 3,
      "title": "Первая статья",
      "body": "Текст статьи",
      "created_at": "2026-11-03T10:00:00Z",
      "updated_at": "2026-11-03T10:00:00Z"
    }
  ],
  "limit": 20,
  "offset": 0
}
```

Пустая страница возвращается с `items: []`, а не `null`. Поля `total` нет.
Ошибки: `400`, `500`.

## Получение: GET /articles/{id}

```bash
curl -i http://localhost:8080/articles/10
```

Успешный ответ: `200 OK`, тело — объект статьи из раздела «Статья в ответах».
Ошибки: `400`, `404`, `500`.

## Создание: POST /articles

В примерах защищённых запросов переменная `TOKEN` содержит токен из [ответа Auth](auth.md).

```bash
curl -i http://localhost:8080/articles \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"title":"Первая статья","body":"Текст статьи"}'
```

Успешный ответ: `201 Created`, тело — созданная статья. Заголовок `Location: /articles/{id}` указывает на её маршрут.
Ошибки: `400`, `401`, `413`, `500`, `503`.

## Изменение: PUT /articles/{id}

```bash
curl -i -X PUT http://localhost:8080/articles/10 \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"title":"Обновлённый заголовок","body":"Обновлённый текст"}'
```

Успешный ответ: `200 OK`, тело — обновлённая статья. Автор сохраняется.
Ошибки: `400`, `401`, `403`, `404`, `413`, `500`, `503`.

## Удаление: DELETE /articles/{id}

```bash
curl -i -X DELETE http://localhost:8080/articles/10 \
  -H "Authorization: Bearer $TOKEN"
```

Тело запроса не требуется. Успешный ответ: `204 No Content`, без тела.
Повторное удаление отсутствующей статьи авторизованным пользователем возвращает `404`.
Ошибки: `400`, `401`, `403`, `404`, `500`, `503`.

## Коды ошибок

Текст `error` предназначен для человека; клиент различает ситуации по HTTP-коду.

| Код | Причина | Пример тела |
| --- | --- | --- |
| `400` | Некорректные поля, JSON, ID или пагинация | `{"error":"invalid title"}` |
| `401` | Отсутствующая или неуспешная авторизация | `{"error":"invalid access token"}` |
| `403` | Попытка изменить или удалить чужую статью | `{"error":"forbidden"}` |
| `404` | Статья или маршрут не существует | `{"error":"article not found"}` |
| `405` | Метод не поддерживается маршрутом; ответ содержит заголовок Allow | `{"error":"method not allowed"}` |
| `413` | Превышен лимит тела | `{"error":"request body too large"}` |
| `500` | Внутренняя ошибка Blog | `{"error":"internal error"}` |
| `503` | Auth не смог подтвердить токен из-за сбоя | `{"error":"authentication service unavailable"}` |
